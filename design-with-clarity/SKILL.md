# Design with Clarity｜清晰设计

让读者看出内容的关系，让使用者能预测自己的操作。清楚地传达信息，也让作品具有适合它的性格。

本技能把两本书的观点转成设计工作方法：从使用者的理解出发，用视觉组织表达内容，再检查设计是否兑现了这个理解。下面的流程与例子是应用归纳，并非原书的一套固定步骤。

## 1. 从当前任务和真实材料开始

读取用户给出的页面、截图、代码、内容或参考。先确定：**谁在什么情境下，需要读懂、比较、决定或完成什么？** 只补足影响当前设计的背景；缺失信息不阻断工作时，说明假设并继续。

评审已有页面时，核对可见信息和实际行为。新建设计时，先用真实内容确定阅读顺序和信息关系。局部修正直接处理相关位置；已授权的视觉重设计，可以充分调整布局与样式。遵守已有功能、品牌及项目约束，不顺手扩展产品范围。

不要把“更高级”“更简洁”直接翻译成大留白、少按钮或一套卡片。先明确希望读者看见什么关系、形成什么感受，再决定形式。

## 2. 按真实的阅读与使用方式判断

Krug 的重要起点，是设计者想象的仔细阅读，与使用者实际的匆忙、分心和背景知识之间存在差距。把下面几种可能性带入具体任务，不把它们当成所有人的固定行为：

- **先扫线索。** 用户未必读完说明才行动。只扫标题、名称、分组和控件时，哪里看起来与目标有关？必要信息能否在需要它的地方被发现？
- **先试一个合理入口。** 不只检查正确路径存在，也检查其他入口为什么可能更像答案；到达后，页面名称、对象和内容是否接续了入口的承诺？
- **边用边理解。** 操作成功不证明理解正确。用户可能自信地把“追加”当作“覆盖”，把单项操作当作批量操作。核对用户可能预测的结果与实际行为。

任务本身可能需要认真思考：比较费用、读懂文章、判断风险。设计应让这些判断所需的信息容易找到和关联，减少猜测控件含义、作用范围与系统状态的负担。

有现成惯例能准确表达操作时，利用它。产品需要新颖表达时，提供可辨认的线索，使人不必先学习设计者的内部分类。

## 3. 指出界面正在暗示什么

对影响当前任务的关键位置，形成一个简短、可核对的判断：

**可见线索 → 可能产生的理解或选择 → 与内容、实际行为的差别。**

例如：“‘合并’可能被理解为更新重复记录，但这里实际只追加；改动必须让执行前的预期与追加行为一致。”这比“按钮文案不清楚”更能决定如何修改。

没有真人观察时，把理解和行为写成有依据的假设；不要虚构犹豫、误点或眼动数据。也不要因为自己知道功能，就假定用户能从界面知道。

先分清问题，再选手段：

| 证据指向的问题 | 优先检查的设计决定 |
| --- | --- |
| 用户要找的概念，在现有名称或分类中没有对应 | 改任务用词、归类或入口承诺；加大按钮不能修复错误含义 |
| 信息已经存在，却在需要时难以发现 | 调整位置、分组、竞争强调与阅读顺序；先判断为何没有被看见 |
| 名称可懂，但对象、范围或结果容易理解错 | 明确对象与动作的关系、必要后果及真实状态 |
| 内容可以理解，但视觉零散、平淡或缺少个性 | 重建版式联系与有意的差异，确定可识别的视觉特征 |

不要为了套分类给页面制造问题。一个关键位置可能同时涉及几种原因。

涉及跨页流程时，从实际入口走到结果，包括用户直接打开详情页的情况。让标题、当前对象、选中状态和返回路径保持连贯；按需要提供定位线索，不把面包屑或引导层当成必加组件。

## 4. 先决定内容关系，再把关系做出来

确定当前范围内：哪些是同一对象的名称、属性、说明和操作；哪些是平级选项；哪些要逐项比较；哪些差异必须被读者察觉。然后同时运用 Williams 的四种视觉手段。它们互相支持，不是四轮各自打勾的检查。

### 亲密性：让信息成为正确的单位

先说清一组包含什么，再安排组内与组间的距离。检查标签、说明和操作实际更接近谁，以及边框、底色、缩进是否给出了相反的归属线索。

例如，字段的说明与下一字段更近，即使全页间距一致，关系仍然错误。应让标签、输入和说明形成同一字段单元；调完后再看长说明和错误提示是否仍归属于它。空白的作用在于组织关系，不在于占得多。

### 对齐：让位置有可追随的依据

为阅读或比较建立共同边缘、基线或列。能指出这条线连接哪些内容，以及为什么要这样连接。需要比较数字时，让同类数值沿同一列排列；为某个元素另起一个位置时，应有内容或构图上的理由。

对齐可以跨越距离联系模块，不要求全页只有一条轴线，也不要求全部左对齐。先建立整体的阅读结构，再修正图标等局部的视觉偏移。

### 重复：把分散的部分联系成一套作品

决定哪些部分应被认作同一种角色、同一个系列或同一品牌，再选可辨认的特征贯穿它们：标题处理、线条、形状、颜色、编号或空间节奏。

除了保持同类控件一致，还可以主动强化一个特征，形成作品的识别度。例如，一组内容共用醒目的章节编号与标题关系，插图和版面大小仍可以变化。稳定的联系让有意的变化更容易被理解；无需把每块内容做成相同的盒子。

### 对比：把该统一与该区分的关系做明确

遇到几个略有不同的字号、灰度或字重时，先判断角色：相同角色就统一；不同角色且需要被辨认，就拉开足够清楚的差别。避免每处都微调一点，却没有形成读者能识别的层级。

选择能表达当前差别的大小、粗细、形态、位置或空间关系。强调一处会改变其他内容的相对显著性，要回看整体。首要内容可以是问题、数据或作品本身，不默认把最大的强调给按钮。

### 把字体当作内容表达的一部分

先分配标题、连续阅读、比较数据、标签和辅助信息的角色，再决定字体关系。判断字形、大小、字重等是在有意协调，还是建立明确对比。多个近似字体、细微字号差不自动构成设计。

字体也传达气质；用真实标题、正文与混排内容检查它是否适合当前作品。字体数量和字号数量不能代替这个判断。跨字体的基线、实际字面大小与可读性，要在渲染后看。

## 5. 作出具体改稿，并解释重要取舍

局部问题选择足以改变错误线索的修正。若名称或间距无法修复真实的分类错误，就调整相关结构。明确要求重设计时，落实能够兑现目标的整体版式，不把“最小”理解为只能调几个像素。

关键方案存在两种合理做法时，比较它们对**同一个任务**的影响：消除了什么猜测，又增加了什么寻找、记忆、比较或等待？不必制作多套完整方案，也无需为每个细节写论证。

- 选择：把选项区别和必要条件放在决策处。点击数只是成本之一；高频重复路径和加载等待也应计入。
- 文案：先修正名称与结构，再决定是否需要解释。删去重复页面用途的空话，保留会改变选择的条件、费用、限制和恢复办法。短文案仍应让人预测结果。
- 反馈：让对象、动作与真实结果对应。选中文件、上传、保存完成是不同状态，不能用同一个“成功”掩盖差别。

新设计或视觉改稿时，把气质落实为相互配合的选择。例如，读书活动可以用书页般的排版节奏、鲜明的章节标题和有联系的手绘元素；这些是当前内容的表达选择，不是通用模板。愉悦、亲近和探索也可以是明确目标，不必给每个趣味细节编造效率收益。

参考 ZaynHao、Honkish 或其他作品时，提取它在特定情境下解决的表达或交互问题，再决定哪些关系值得迁移。需要时读取 [视觉与交互打磨](references/visual-polish.md)。参数和技巧用于实现已经作出的判断，不替代判断。当前项目有认可的成熟实现时，优先读取它；多页任务可先做好代表性区域再推广。

## 6. 回到同一个任务，检查改动是否成立

改动前明确希望改变的理解或阅读关系，改后检查同一件事。例如，修改字段分组后，要检查说明是否还可能被看成属于下一字段；不能只报告间距已统一。

- **视觉检查**：在相同内容和视口下比较改前改后。先扫分组、共同边缘和强调，再读细节。画面表达的归属、顺序和异同是否符合内容？有意的个性是否仍成立？
- **实现检查**：运行受影响操作，核对对象、范围、结果和恢复路径；按改动查看长文本、窄屏、焦点、失败或连续操作。代码正确、控件可点，仍不能证明含义被理解。
- **理解验证**：涉及核心入口、分类或动作含义时，给出一个真实任务来检验判断。观察人怎样开始、预测结果和发现偏离；不要用“这个按钮明显吗”代替任务，也不要替界面解释。条件允许时及早做，不必等全部完成。

明确分开可见事实、设计假设、运行结果和实际用户观察。缺少运行或真人观察条件时，交代尚未验证什么，继续完成已有证据支持的改进，不把自查称为用户测试。

优先修复影响当前目标的问题。达到目标后停止；迅速恢复且没有实际影响的轻微绕路，不自动成为重做流程的理由。

## 输出与按需参考

直接完成用户要求的设计、实现或评审；按任务规模说明关键决定。重要改动应能回答：**原来在暗示什么，希望表达什么，具体怎样改变，如何检查。** 新设计说明内容关系与选择依据，无需编造旧版缺陷。

只写“优化层级、增强对比、增加留白”不构成有效建议。给出对象、位置、内容或样式关系；参数可以是候选值，但应在实际尺寸和内容下核对。
